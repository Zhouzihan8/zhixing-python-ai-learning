# S6-P01 小型文档问答：动手版

完成 S6-U07 后组合本阶段知识；学到对应函数时即可分步完善。

把 S1 的文本处理、S4 的相似性概念与 S5 的评价合起来。先实现可检查的检索和上下文，再接向量检索与真实生成。

## 从这里开始

只编辑“我的项目.py”，入口、输入与检查代码已经接好；先看函数说明和 data/检查用例.json，明确输入输出。函数暂未实现时运行失败是正常的。

1. 实现 retrieve，打印命中的资料、分数和来源；测试无命中时返回空列表。
2. 完成 make_context 并生成 outputs/result.json；此时只有检索与上下文，不是完整 RAG。
3. 在本课框架脚本准备完成后，先运行 S6-U02 的 retrieve.py，再运行 S6-U03 的 generate_rag.py，检查真实回答的引用。
4. 使用有答案和无答案问题比较；需要持久化时依次选学 SQLite、MySQL，再把已有函数包装为 FastAPI 接口。

## 运行与结果

在本目录终端执行：

~~~powershell
py -3 检查结果.py
py -3 运行项目.py
~~~

检查通过后，实际结果会写入 outputs/result.json。更换一份输入并解释结果；不能只让固定用例变绿。再回头看是否有把预期答案硬编码到函数中。

## 文件与求助顺序

- 我的项目.py：自己的实现，导出课程时保留。
- data/：小型输入和公开检查例子。
- 运行项目.py：负责读入、调用与保存，可打断点观察。
- 检查结果.py：检查函数的输入输出，不需要现在掌握检查器写法。
- 参考答案/：最后需要时再看；先定位失败用例、查本课提示。

## 项目收尾：把基础应用到真实流程

先用词项检索检查资料身份；准备模型后运行“真实向量问答.py”，保存命中原文和回答。至少准备一题有证据、一题措辞变化、一题无答案；分别判断检索、引用、回答。需要保存和共享时才接数据库与 API 选修。

- `真实向量问答.py`：本项目的真实框架衔接脚本。

框架依赖在对应阶段准备。真实模型脚本使用 MODEL_ID（编码器另用 EMBEDDING_MODEL_ID），填写已确认的模型名或本地路径；首次远程加载可能下载文件。网页不会替你预先安装或下载。这里没有将未运行的框架脚本标为已训练成功。
